# Database Rules

## Repositories

- Per feature: the `Repository` interface lives in `repository.go` next to
  its consumer (`Service`); the pgx implementation `Repo` lives in
  `postgres.go` with `var _ Repository = (*Repo)(nil)`.
- Repos hold a `*pgxpool.Pool` and translate driver errors at this boundary:
  `pgx.ErrNoRows` → the feature's `ErrNotFound`-style sentinel, PgError
  `23505` → the conflict sentinel (`user.ErrEmailTaken`). Nothing above
  `postgres.go` imports pgx error types.
- Document error behavior on the interface methods
  (`// Get returns ... or ErrNoSession.`).

## SQL Conventions

- Plain SQL written out per query — no query builders, no ORM.
- Named placeholders via `pgx.NamedArgs` (`@user_id`), never positional `$1`
  in feature repos (small fixed queries in `platform` and `testdb` may use
  `$1`).
- Collect rows with `pgx.CollectRows` / `pgx.CollectExactlyOneRow` +
  `pgx.RowToStructByName[T]`; struct fields carry `db:` tags. Keep a
  `<name>Columns` const so every query selects the same columns.
- The `Query → Collect` pattern ignores the Query error on purpose
  (`rows, _ :=`) — Collect surfaces it.
- Writes use `RETURNING` and return the fresh row; every `UPDATE` sets
  `updated_at = now()`.
- Enforce ownership in SQL (`WHERE id = @id AND user_id = @user_id`), not in
  Go — zero rows affected means the feature's not-found sentinel.

## IDs

- UUIDv7 primary keys generated by PostgreSQL: `DEFAULT uuidv7()`.
- In Go, ids are plain `string` — pgx converts uuid ↔ string both ways.
  No uuid library. Validate path-parameter ids with the local `isUUID`
  helper (see `internal/note/http.go`) and treat garbage as not found.

## Migrations

- Embedded in `migrations/` and applied on startup and by `testdb`, in
  lexical filename order, each file in one transaction
  (`internal/platform/database/migrate.go`).
- **Append-only**: never edit an applied migration; add a new numbered file
  (`just makemigration add_toys_table`). Never renumber.
- Plain SQL only — no goose/tool directives, no down migrations. Roll
  forward with a new migration.
- One file may hold multiple statements (simple protocol). But no
  `CREATE INDEX CONCURRENTLY` — it cannot run inside a transaction.
- Schema style: `timestamptz` everywhere; `text` + `CHECK` instead of ENUMs;
  case-insensitive uniqueness via `UNIQUE INDEX ... (lower(email))`;
  `ON DELETE CASCADE` for owned rows; index foreign keys, matching the
  list query's `ORDER BY` when possible.
- Mirror any value `CHECK` in Go (see `maxTextLength` in
  `internal/note/service.go`) and keep the two in sync.
